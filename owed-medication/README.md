# คลินิกเติมยา (ระบบนัดเติมยา)

ระบบติดตามยาที่จ่ายไม่ครบตามแพทย์สั่ง แยกจากระบบยารีฟิวเดิม (`refill-medication/`) และใช้ฐานข้อมูลของตัวเอง

- `index.html` คือหน้าเจ้าหน้าที่ แต่ละคนเข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่านของตัวเอง
- `status.html` คือหน้าที่ผู้ป่วยเปิดจาก QR บนใบแจ้ง ไม่ต้องเข้าสู่ระบบ
- `core.js` คือกฎของระบบที่ใช้ร่วมกันทั้งสองหน้า เช่น สถานะ การแบ่งนัด วันหยุด ข้อความถึงผู้ป่วย และรหัสไปรษณีย์
- `config.js` เก็บ Web App URL ของฐานข้อมูล และที่อยู่ผู้ส่งบนจ่าหน้าซอง
- `apps-script/Code.gs` คือ backend บน Google Apps Script

## ติดตั้งฐานข้อมูลใหม่

1. สร้าง Google Sheet ใหม่ ตั้งชื่อตามสะดวก เช่น "คลินิกเติมยา"
2. ในชีตนั้นเปิดเมนู **Extensions → Apps Script** ลบโค้ดตัวอย่าง แล้ววางเนื้อหาทั้งหมดของ `apps-script/Code.gs`
3. เปิด **Project Settings → Script Properties** เพิ่ม Property ชื่อ `API_KEY` ค่าเป็นข้อความสุ่มยาวอย่างน้อย 16 ตัวอักษร เก็บค่านี้ไว้กับผู้ดูแล
4. กด **Deploy → New deployment** เลือกชนิด **Web app** ตั้ง *Execute as* เป็น **Me** และ *Who has access* เป็น **Anyone** แล้วกด Deploy และอนุญาตสิทธิ์
5. คัดลอก Web app URL ที่ลงท้ายด้วย `/exec` มาใส่ใน `config.js` ที่ `endpoint: '…'` แล้ว push ขึ้น GitHub Pages
6. เปิดหน้าเจ้าหน้าที่ กด **ตั้งผู้ดูแลคนแรก / กู้คืนผู้ดูแล** ใส่ API key จากข้อ 3 พร้อมชื่อ ชื่อผู้ใช้ และรหัสผ่านของผู้ดูแล
7. ผู้ดูแลกด **👥 ผู้ใช้** เพื่อเพิ่มเจ้าหน้าที่ แล้วแจ้งชื่อผู้ใช้และรหัสผ่านเริ่มต้นให้แต่ละคนไปเปลี่ยนเองที่ปุ่ม **🔑 รหัสผ่าน**

ระบบจะสร้างแท็บ `Slips` (ใบแจ้ง) `Users` (ผู้ใช้) `Clinics` (คลินิก) `AuditLog` (ประวัติการใช้งาน) `Holidays` (วันหยุดราชการ) และ `DrugNames` (รายชื่อยา) ให้เองเมื่อใช้งานครั้งแรก

ถ้าแก้ `Code.gs` ภายหลัง ต้องกด **Deploy → Manage deployments → Edit → Version: New version** ทุกครั้ง URL จะยังเป็นค่าเดิม

## ผู้ใช้และสิทธิ์

| ทำได้ | เจ้าหน้าที่ | ผู้ดูแล |
|---|---|---|
| บันทึก แก้ไข เลื่อนสถานะ พิมพ์ใบแจ้ง จ่าหน้าซอง นำเข้า Excel จองใบเปล่า | ✓ | ✓ |
| ดูวันหยุด เปลี่ยนรหัสผ่านของตัวเอง | ✓ | ✓ |
| ลบใบแจ้ง เพิ่มหรือลบวันหยุด | | ✓ |
| เพิ่ม แก้ชื่อ หรือลบคลินิก (⚙ ตั้งค่า → คลินิก) | | ✓ |
| เพิ่ม ระงับ เปลี่ยนสิทธิ์ ตั้งรหัสใหม่ให้ผู้ใช้ และดูประวัติการใช้งาน | | ✓ |

- ใบแจ้งแต่ละใบเก็บประวัติว่าใครสร้าง ใครแก้อะไร และใครเลื่อนสถานะ เมื่อไร แสดงในแผงรายละเอียด
- แท็บ `AuditLog` เก็บทุกการกระทำ รวมการเข้าสู่ระบบ การลบใบแจ้ง และการจัดการผู้ใช้ ผู้ดูแลดูได้ที่ **👥 ผู้ใช้ → ประวัติการใช้งาน**
- ผู้ดูแลลดสิทธิ์หรือระงับตัวเองไม่ได้ ระบบจึงมีผู้ดูแลอย่างน้อยหนึ่งคนเสมอ ถ้าผู้ดูแลลืมรหัส ใช้ **กู้คืนผู้ดูแล** ด้วย API key

## ความปลอดภัย

- รหัสผ่านเก็บแบบ hash ผสม salt ไม่มีใครเห็นรหัสจริง รวมถึงผู้ดูแล
- ใส่รหัสผิดติดกัน 5 ครั้ง ชื่อผู้ใช้นั้นถูกล็อก 15 นาที
- ระงับผู้ใช้แล้วมีผลทันที แม้คนนั้นยังเปิดหน้าเว็บค้างไว้
- ต้องเข้าสู่ระบบทุกครั้งที่เปิด รีเฟรช หรือย้อนกลับมาที่หน้าเจ้าหน้าที่ สิทธิ์เข้าใช้อยู่ในหน่วยความจำของหน้าเท่านั้น และหมดอายุใน 6 ชั่วโมง
- API key ใช้แค่ตอนตั้งหรือกู้คืนผู้ดูแล และไม่ถูกบันทึกไว้ในเครื่อง
- หน้าผู้ป่วยได้รับเฉพาะชื่อที่ปิดนามสกุลแล้ว รายการยา และวันนัด ไม่ได้รับ HN เบอร์โทร ที่อยู่ หรือประวัติการแก้ไข
- ข้อความที่ผู้ป่วยเห็นใช้คำว่า "ยาตามนัด" ไม่บอกว่ายาหมดหรือไม่พอ

## วันหยุดราชการ

ข้อมูลตั้งต้นมีเฉพาะวันหยุดที่วันที่ตายตัว วันหยุดตามจันทรคติ (มาฆบูชา วิสาขบูชา อาสาฬหบูชา เข้าพรรษา) และวันหยุดพิเศษตามมติ ครม. ผู้ดูแลต้องเพิ่มเองทุกปี จากปุ่ม **📅 วันหยุด** หรือแก้ในแท็บ `Holidays`

## เปลี่ยนจัดส่งแล้วเป็นรับครบแล้วอัตโนมัติ

1. อัปเดตโค้ด Apps Script ด้วยไฟล์ apps-script/Code.gs รุ่นล่าสุด
2. ใน Apps Script Editor เลือกฟังก์ชัน installAutoCompleteDeliveries แล้วกด Run หนึ่งครั้งและอนุญาตสิทธิ์ ระบบจะติดตั้งตัวตรวจทุกชั่วโมงโดยไม่สร้างซ้ำ
3. อัปเดต deployment เดิมด้วย New version ตามขั้นตอนด้านบน

ตัวตรวจทำงานแม้ไม่เปิดเว็บ เฉพาะการรับยาทางไปรษณีย์ที่มีสถานะ delivery และประวัติเปลี่ยนสถานะล่าสุดของนัดเป็น delivery ครบ 72 ชั่วโมงแล้ว จึงเปลี่ยนเป็น received และบันทึกประวัติ เมื่อย้อนสถานะแล้วจัดส่งใหม่จะเริ่มนับใหม่ ไม่ใช้ updatedAt ของทั้งใบแจ้งแทนเวลาจัดส่ง รายการเดิมที่ไม่มีประวัติเวลาจัดส่งจะไม่ถูกเปลี่ยนอัตโนมัติ การตรวจทุกชั่วโมงอาจเปลี่ยนหลังครบกำหนดประมาณหนึ่งชั่วโมงตามตารางทำงานของ Google

## ข้อมูลโรงพยาบาลที่แก้ไขได้จากหน้าตั้งค่า

อัปเดต Code.gs และ Deploy เป็น New version ก่อนใช้งาน จากนั้นผู้ดูแลเปิด ตั้งค่า → ข้อมูลโรงพยาบาล กรอกชื่อโรงพยาบาล หน่วยงาน โทรศัพท์ เบอร์ต่อ ที่อยู่ และข้อความผู้ส่ง แล้วบันทึก ค่าถูกเก็บใน Script Property ORGANIZATION_PROFILE ของฐานข้อมูลนี้ ใช้ร่วมกันทุกเครื่อง หน้า QR และข้อความติดต่อในใบพิมพ์ บัญชี staff อ่านข้อมูลได้แต่เปลี่ยนไม่ได้ ไม่มีการเพิ่ม trigger สำหรับส่วนนี้ โลโก้ยังใช้ไฟล์เดิมในชุดเว็บ
